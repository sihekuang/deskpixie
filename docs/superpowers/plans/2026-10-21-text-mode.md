# Text Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A 🔊/💬 toggle beside the session count; in 💬 mode a quick message box under Pixie sends text straight to the coordinator and shows only its `<spoken>` answer, with Stop.

**Architecture:** Go owns the `replyMode` setting, sending typed messages as coordinator jobs, routing those jobs' spoken lines to a `chat.line` event instead of voice/bubble, Stop, and the hotkey decision. Swift draws the toggle and card in the roster's panel and runs a small, tested card state machine in DeskPixieCore.

**Tech Stack:** Go (core/settings, core/agent, core/app), Swift/SwiftUI (mac/DeskPixie, DeskPixieCore).

**Spec:** `docs/superpowers/specs/2026-10-21-text-mode-design.md`

## Global Constraints

- Voice mode behaviour is unchanged; `replyMode` default `"voice"`.
- `replyMode` values exactly `"voice"` | `"text"`; Settings ▸ Pixie; `ApplyLive`.
- Events: `chat.line {job, status, text}` (status `working|question|done|failed`), `chat.focus {}`, `replyMode {mode}`. Calls: `chat.send {text}` → `{job}` or error, `chat.stop {}`, `chat.mode {}` → `{mode}`.
- Card copy: placeholder "Message Pixie"; caption "Pixie"; "Thinking…", "Answering…", "Stop", "Stopped.".
- Look: like `AgentRosterView` (capsule `.regularMaterial` + `.separator` stroke; card 260 wide, radius 12, padding 6).
- Tests never touch the real home/settings (AGENTS.md).

## Review Focus

- Sending while delegation is off (no coordinator / agent disabled): the card must show the reason, not hang on "Thinking…" — test in Task 2 (`chat.send` error) and Task 4 (model `failed(reason)`).
- The coordinator stops without a `<spoken>` block for the typed job ("The coordinator stopped before finishing: …" from `failJobSaying`): must reach the card as `failed` — test in Task 2.
- A typed job's permission request (line with `Token`): must still reach the bubble/notification (so it can be allowed) and also the card — test in Task 2.
- Empty/whitespace message: no job, send disabled — tests in Task 3 (`chat.send` rejects) and Task 4.
- Restart with a typed job open: the typed mark is in memory only, so its later lines take today's route (spoken/bubble) — acceptable; covered by Task 2's "untyped job unchanged" test.

### Task 4: The card model and events in DeskPixieCore

**Files:**

**Interfaces:**
- Produces:
  - `public struct ChatLine: Decodable, Sendable, Equatable { job: String; status: String; text: String }`.
  - `public struct QuickChatModel` (value type, driven by the controller):
    - `enum Phase: Equatable { ready, thinking, answering, done, stopped }`
    - `var phase`, `var shown: String` (text typed out so far), `var full: String`, `var job: String?`, `var open: Bool`, `var mode: String` ("voice"/"text")
    - `var showsStop: Bool` (thinking or answering), `func canSend(_ draft: String) -> Bool` (non-blank, not thinking/answering), `var statusText: String?` ("Thinking…" / "Answering…" / nil)
    - `mutating func sent(job: String)` → thinking, clears text; `mutating func failedToSend(_ reason: String)` → done with `full = shown = reason`
    - `mutating func apply(_ line: ChatLine)`: ignores another job's line; `working` → thinking with `shown = full = text`; `question|done|failed` → answering with `full = text`, `shown = ""`
    - `mutating func tick() -> Bool`: answering reveals the next word of `full` (returns false when nothing changed); when all shown → done
    - `mutating func stopped()`: answering → shows all of `full`, done; thinking → stopped; appends nothing to the text (the view adds "Stopped.")
